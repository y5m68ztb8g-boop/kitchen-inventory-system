# 信息录入与待采购收集设计

## 目标

把首页现有的采购入口调整为一个只负责收集和整理待采购信息的模块。它可接收酒店白板、员工留言照片、活动资料 PDF、Excel/CSV 清单，整理为可人工核对的待采购项目，并在你修正确认后转入未来独立的采购窗口。

该模块不创建订单、不向供应商发送信息、不修改库存，也不把上传的文件当作历史发票导入。下单与库存盘点保留给后续独立模块。

## 首页与入口页

首页第三个模块使用摄像头图标，名称显示为“AI录入”，链接到 `#purchasing`。

`#purchasing` 默认显示“信息录入”入口页，提供两个清晰的大按钮：

1. “AI拍照识别录入”：在手机上点击后调用后置摄像头；同时保留选择已有照片的备用方式。
2. “手动上传录入”：选择已有文件，支持 JPG、PNG、HEIC、WebP、PDF、XLSX、XLS、CSV。

入口页不立即打开摄像头。只有用户选择“AI拍照识别录入”后才触发相机，符合手机浏览器的权限规则。

## 解析与审核流程

所有来源最终转换成同一份可编辑审核表。审核表保留部门、原始文字、产品名、数量、单位、备注和置信度；用户可以修改、删除或增加条目。低于 0.8 置信度的行必须勾选人工复核后才可保存。

| 来源 | 服务器处理方式 | 审核表结果 |
| --- | --- | --- |
| 拍照或上传图片 | 在服务器调用 OpenAI 视觉识别 | 提取明确写出的待采购项目，保留原始手写文字 |
| PDF | 服务器提取文本；扫描型或版面复杂的页转为图像后交给视觉识别 | 提取明确的采购需求；活动日期、人数等上下文写入一般备注 |
| Excel/CSV | 服务器读取工作表和常见列名，例如部门、产品、数量、单位、备注 | 按行生成待采购项目；无法识别的列或数量保持为空，不猜测 |

识别只提取文件中明确表达的信息。对于活动资料，系统会保留相关背景备注，但不会自行推断“应该购买多少”。

用户可在审核表中反复修正、删除、增加或合并项目。每次保存保留为 `Pending` 草稿；当内容已经是最终版本时，点击“转入采购清单”，项目状态变为 `ReadyForPurchase`。这个动作不下单，只把整份已确认结果交给共享采购队列。

未来独立的采购窗口只读取 `ReadyForPurchase` 项目，因此可以直接展示这份最终清单，继续讨论、调整和手工下单，而不需要再次录入或复制内容。转入前后都继续显示建议的历史商品、供应商、货号、包装、最近价格和当前库存数量。

## 数据与审计

新增通用的 `purchase_intakes` 和 `purchase_intake_items` SQLite 表，记录来源类型、原始文件名、格式、大小、压缩后的文件内容、识别备注、审核项目、草稿保存时间和转入采购队列的时间。原有 `whiteboard_scans` 与 `whiteboard_scan_items` 保留，不删除已有白板审计记录。

原始上传文件只保存在服务器 SQLite 数据库中；图片会按现有方式压缩，PDF 和表格保留原文件以便审计。浏览器本地存储不保存已确认的采购信息。

## 接口与安全

新增服务器端上传接口，以统一处理图片、PDF、Excel 和 CSV。OpenAI API 调用仅在服务器端进行，继续只从 `OPENAI_API_KEY` 环境变量读取密钥。浏览器不会收到密钥，也不会直接调用 AI 服务。

上传需要校验文件格式、大小、空文件、损坏文件、无法读取的 PDF/表格、AI 服务不可用和不符合结构的识别结果。所有提示在界面中显示中文，并保留重新选择文件或重试识别的路径。

## 范围边界与后续空间

本次完成“采集、识别、审核、草稿保存、转入采购队列、历史匹配”。以后可在同一个入口页增加第三种“员工文字留言”来源，也可在独立的采购模块中汇总所有 `ReadyForPurchase` 项目。库存价值、库存数量和供应商购物车不由本模块自动改变。

## 验证

自动化测试覆盖入口页路由、手机拍照选择、各文件格式校验、图片/PDF/表格解析转换、低置信度复核、SQLite 保存、历史匹配和原文件审计读取。浏览器端到端测试必须使用隔离端口和临时数据库，不能复用运行中的酒店系统或 Supabase 数据。
